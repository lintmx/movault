# Movault

面向个人的日本电影前售券管理工具。集中保存購入番号、暗証番号与兑换状态，支持实体券、电子券和浏览器本地 OCR。

移动端优先，无需账号或后端服务。数据保存在当前浏览器，资源缓存完成后可离线使用。

[快速开始](#快速开始) · [使用说明](#使用说明) · [数据安全](#数据安全) · [部署](#部署) · [参与贡献](#参与贡献) · [MIT License](LICENSE)

## 功能

- **电影管理**：新建、编辑、删除电影，上传海报，设置上映日期和默认单次价格。
- **前售券管理**：实体券固定兑换一次；电子券支持多次兑换，分别记录未使用、待确认和已使用次数。
- **多种录入方式**：单张录入、连续录入、批量粘贴；重复号码组合会提示核对。
- **本地 OCR**：从相机或相册导入固定版式实体券，支持自动定位、透视校正、手动调整和原图对照。
- **查找与复制**：按購入番号搜索，按状态和券种筛选，分别复制号码或一次复制整组凭证。
- **统计与备份**：查看兑换进度和日元金额分布，导出完整 JSON 备份，合并或覆盖恢复。
- **离线使用**：支持 PWA，应用资源与 OCR 资源分别缓存。

## 快速开始

### 环境要求

- Node.js 24 或更高版本。
- pnpm 12.9.1，与 `package.json` 中的 `packageManager` 保持一致。
- 支持 IndexedDB、Web Worker、WebAssembly 和 Canvas 的现代浏览器。

克隆或下载仓库后，在项目目录执行：

```sh
pnpm install --frozen-lockfile
pnpm dev
```

打开终端显示的地址，通常为 `http://localhost:5173`。项目无需配置环境变量、数据库或 API 密钥。

开发和构建命令会自动将 OCR 引擎、模型及相关许可证准备到 `public/ocr/`。该目录为生成产物，无需提交到 Git；完整静态资源约 25 MiB，进入应用后会后台缓存当前设备需要的约 17 MiB（HTTP 压缩后更小），恢复联网时会重试。拍照识别复用进行中的下载或已有缓存，识别引擎仅在使用时启动；加载进度可见，失败可重试。

### 常用命令

| 命令 | 说明 |
| --- | --- |
| `pnpm dev` | 准备 OCR 资源并启动开发服务器 |
| `pnpm typecheck` | TypeScript 类型检查 |
| `pnpm lint` | Oxlint 检查 |
| `pnpm build` | 准备 OCR 资源、检查类型、构建并生成 Service Worker |
| `pnpm preview` | 在本地预览 `dist/`，需先执行构建 |

## 使用说明

1. 新建电影，填写上映日期和默认单次价格，按需上传海报。
2. 添加实体券或电子券。購入番号为 10 位数字，暗証番号为 4 位数字，前导零会保留。
3. 兑换或转交凭证后，手动更新对应次数的状态。复制号码不会自动更改状态。
4. 首次进入时阅读当前平台的数据保留说明，按需添加到主屏幕并申请存储保护；定期进入「数据管理」导出 JSON 备份。

### 批量录入

每行填写一组購入番号和暗証番号，可用空格、Tab 或逗号分隔：

```text
0123456789 0123
1234567890 4567
```

解析后可检查和修改各行内容；有效记录可以先保存，异常行会保留供继续修正。以上号码仅用于格式演示。

### 拍照识别

OCR 使用 Tesseract.js 和 OpenCV.js，在浏览器内处理图片，不调用云端识别接口。仅针对当前固定版式实体券；电子券使用手动或批量录入。

首次使用需要联网准备识别资源。自动定位失败时，可调整卡片四角或直接框选两个号码区域。识别后应逐位核对来源图片，点击「确认并保存」才会创建记录。原照片和裁剪图不写入备份或业务数据库。

「离线资源已就绪」表示常规管理可离线使用；OCR 还需在拍照识别页面显示「可离线识别」。识别准确率受版式、清晰度、反光和设备影响，真实手机与多样本验证仍需持续完善。

### 数据与隐私

- 电影、海报、号码、兑换状态和备注保存在当前站点的 IndexedDB 中。
- 不提供账号、云端同步或跨设备自动同步。不同浏览器、域名或端口拥有各自的数据。
- 清除站点数据、更换设备或浏览器回收存储可能导致数据丢失；离线缓存不能替代 JSON 备份。
- 备份包含明文凭证和海报，请妥善保管，勿将真实备份、票券照片或号码提交到公开仓库和 Issue。
- 合并导入按内部 ID 去重，冲突时保留本地记录；不同 ID 即使号码组合相同也会导入，并提示核对。覆盖导入会替换全部本地数据，需再次确认。
- 多个页面同时编辑时，保存会检查本地数据是否已变化；遇到冲突请先保留当前输入，再刷新重试。

## 数据安全

**Movault 没有服务端副本。浏览器本地保存、离线缓存和持久存储授权都不能替代文件备份。** 刷新或正常关闭后，成功保存的数据通常仍在；手动清除网站数据、卸载浏览器、设备损坏或浏览器的自动清理可能导致数据丢失。

### 不同平台的保留规则

| 平台 / 使用方式 | 风险与建议 |
| --- | --- |
| iPhone / iPad Safari 普通标签页，以及适用相同策略的 WebKit 浏览器 | ITP 可清理累计 7 天 Safari 使用期间未与本站交互的网站数据，包括 IndexedDB；不是保存后经过 168 小时必然删除。即使 `persist()` 返回 `true`，也不能据此豁免 ITP。建议添加到主屏幕，并保留本机文件备份。 |
| iPhone / iPad 主屏幕 Web App | WebKit 明确豁免主屏幕 Web App 的这项 ITP 清理，但仍需防范手动清理、存储回收和设备丢失。固定从桌面图标进入。 |
| macOS Safari | 普通标签页有同类 ITP 风险；可通过「文件 → 添加到程序坞」作为独立 Web App 使用。 |
| Android / 桌面 Chrome、Edge 等 Chromium 浏览器 | 没有 Safari 的固定 7 天规则，但默认存储可在空间不足时被回收。`persist()` 是否获批由浏览器决定，安装应用不等于自动获批。 |
| Android / 桌面 Firefox | 没有 Safari 的固定 7 天规则；申请持久存储时可能弹出权限窗口。未获批时仍需考虑空间不足导致的回收。 |
| 微信、QQ 等应用内浏览器 | 由内核和宿主应用共同决定存储策略，可能与系统浏览器隔离，清理宿主应用可能清除数据。建议在系统浏览器中录入。 |
| 无痕 / 隐私模式 | 数据通常随无痕会话结束而清除，不适合长期保存票券。 |

iOS 第三方浏览器应以实际内核和宿主策略为准，不能按浏览器名称套用 Android 的结论。浏览器、主屏幕 Web App、不同设备以及不同协议、域名或端口之间不会自动共享本项目数据。切换入口前先导出，新入口没有数据时再导入。

首次进入会显示平台提示，用户可点击「申请保护并继续」请求持久存储，也可稍后在「数据管理 → 查看数据安全说明」中申请。正式部署需要 HTTPS。授权主要保护数据不被存储空间回收，不防止用户主动清理，也不绕过 Safari 的 ITP 隐私规则；拒绝授权不影响正常使用。

### 保存到本机的备份

- 文件名使用设备本地年月日、24 小时时间和六位随机数字，例如 `movault_backup_2026-11-03_14-30-05_472819.json`；备份内部的 `exportedAt` 使用 ISO 时间。
- 浏览器支持分享该 JSON 文件时，导出会打开系统分享面板。iPhone / iPad 选择「存储到文件 → 在我的 iPhone / iPad」，Android 选择系统提供的本地文件保存入口；无需使用云盘。系统具体选项取决于设备和已安装应用。
- 不支持文件分享时直接下载。分享失败时可选择「直接下载」，再通过系统文件管理器确认文件位于本地文件夹；浏览器的默认下载位置可能需要用户自行调整。
- 新增、编辑、删除或导入数据后，如果尚未导出对应版本，重新打开、刷新或从后台返回应用时会提醒备份；数据管理页面直接显示待导出状态。忽略提醒不会清除待备份标记。升级前已有的数据因没有导出记录，会提示先备份一次。
- 分享成功返回或下载发起后记录本次导出的数据版本，取消或失败不更新记录。若本地数据已在其他页面变化，不覆盖导出记录，并提示刷新后重新导出。网页无法确认系统面板最终选了哪个位置、下载是否真正完成，请自行检查文件；导出期间产生的新修改仍需再次备份。
- 保留数份不同时间的备份，避免误删后的导出覆盖唯一副本。备份包含明文凭证，请妥善保管。恢复时，在「数据管理」选择 JSON 文件，核对后合并或覆盖导入。

浏览器清除站点数据时，备份提醒和首次提示的记录也可能一起丢失，应用无法仅凭空数据库判断是否曾经有数据。因此请把实际备份文件保存在浏览器之外。

规则参考：[WebKit 跟踪防护与主屏幕豁免](https://webkit.org/tracking-prevention/)、[WebKit 存储策略](https://webkit.org/blog/14403/updates-to-storage-policy/)、[WebKit 对 persist 与 ITP 的说明](https://github.com/WebKit/WebKit/pull/48369#issuecomment-3116516364)、[浏览器存储与清理规则](https://developer.mozilla.org/en-US/docs/Web/API/Storage_API/Storage_quotas_and_eviction_criteria)。

## 部署

项目构建为纯静态文件，可部署到 Vercel 或其他静态托管服务：

```sh
pnpm install --frozen-lockfile
pnpm build
```

发布完整的 `dist/` 目录，包括 `ocr/`、`sw.js`、图标和 Web App Manifest。

| 配置项 | 值 |
| --- | --- |
| 安装命令 | `pnpm install --frozen-lockfile` |
| 构建命令 | `pnpm build` |
| 输出目录 | `dist` |

仓库包含 Vercel 的 SPA 路由回退配置。使用其他服务器时，应优先提供实际静态文件，并将 `/movies/...`、`/data` 等页面路由回退到 `index.html`。

当前路由和 PWA 配置以域名根路径 `/` 为基础，不直接支持 `/movault/` 等子路径。正式使用请启用 HTTPS；本地开发可使用 localhost。Service Worker 只在生产构建中注册，验证离线功能请使用 `pnpm build && pnpm preview`。

更新后若仍显示旧页面，关闭该站点的全部标签页和 PWA 窗口再重新打开，让等待中的 Service Worker 生效。无需为更新清除站点数据。

## 技术栈与目录

React、TypeScript、Vite、Radix Colors / Dialog、Lucide、Tesseract.js、OpenCV.js、IndexedDB、Service Worker。

```text
src/
  App.tsx              页面路由与应用状态
  data.ts              数据模型、存储、备份校验与统计
  forms.tsx            电影和前售券录入
  MovieDetail.tsx      券列表、筛选与状态修改
  DataManagement.tsx   JSON 备份导入与导出
  OcrScanner.tsx       拍照识别与人工确认界面
  ocr.ts               OCR Worker 与资源缓存
  ocr-geometry.ts      区域坐标与几何处理
  ui.tsx / styles.css  通用界面组件与样式
scripts/
  prepare-ocr.mjs      准备同源 OCR 静态资源
  ocr-engine.js        图像处理与文字识别 Worker
  generate-sw.mjs      生成离线缓存 Service Worker
public/                图标、PWA 配置及生成的 OCR 资源
```

项目需求与实现约束见 [PRD.md](PRD.md)、[DESIGN.md](DESIGN.md) 和 [OCR_DESIGN.md](OCR_DESIGN.md)。
